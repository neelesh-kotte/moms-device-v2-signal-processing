# MOM Device Hardware Validation Checklist

**Project:** MOM SenseLoop V3 - Low-cost abdominal-acoustic data capture prototype  
**Hardware Target:** ESP32-WROOM-32 + MAX4466 amplifier + stethoscope acoustic coupling  
**Firmware Version:** MOM SenseLoop 1.1  
**Protocol Version:** mom-provisioning-v1  
**Date Updated:** 2026-10-01  

---

## Pre-Testing Requirements

### Required Hardware
- ESP32-WROOM-32 development board
- MAX4466 microphone amplifier (fixed gain)
- Stethoscope with acoustic coupling
- USB power bank or stable USB power source (5V, ≥500mA)
- USB-to-Serial adapter or direct USB to computer (for provisioning only)
- 2.4 GHz Wi-Fi network

### Required Configuration
- Firmware: `firmware/mom_senseloop/mom_senseloop.ino`
- USB Serial: 115200 baud
- GPIO32: analog audio input from MAX4466 output
- 3V3: MAX4466 VCC
- GND: MAX4466 GND
- Expected serial port: `/dev/cu.usbserial-*` (macOS) or similar

### Expected Protocol
- JSON over USB serial at 115200 baud
- Commands: `identify`, `scan_wifi`, `provision`, `heartbeat`, `record_session`
- All messages terminated with newline (`\n`)
- HTTPS communication from ESP32 to Supabase backend
- Device polling interval: 1.5 seconds
- Heartbeat interval: 60 seconds

## Known Limitations

### Hardware Constraints
- **No FFT on device:** ESP32 firmware computes only statistical summary (mean, stddev, clipping), not spectral analysis
- **No I2S audio:** Uses analog ADC only, not I2S MEMS microphone
- **No real-time processing:** Waveform/statistics computed only after full capture completes
- **Fixed 8 kHz sample rate:** Not configurable at runtime
- **Single-channel only:** Mono audio capture

### Firmware Constraints
- **No medical classification:** Firmware does not detect hunger, disease, or medical conditions
- **No automatic transmission:** Only responds to HTTPS polling from cloud; device does not initiate calls
- **Limited malformed-input handling:** Some protocol violations may cause silent rejection rather than error reporting
- **Battery life untested:** Assumes continuous USB power; no battery-specific optimization

### Website Constraints
- **Browser-based provisioning only:** Requires desktop browser with Web Serial API (Chrome/Edge on Windows/Linux/macOS)
- **No mobile app:** Mobile browsers cannot access USB serial
- **Firebase domain requirement:** GitHub Pages domain must be added to Firebase authorized domains in advance
- **No offline mode:** Requires live Supabase connection for all operations

## How to Interpret Results

### PASS
All observable behavior matches expected behavior. No errors, crashes, or unexpected states.

### FAIL
Observable behavior does not match expected behavior. Record exact discrepancy and provide evidence.

### BLOCKED
Test cannot be performed due to missing external resource:
- Hardware not available
- Wi-Fi network not accessible
- Cloud credentials not configured
- Browser incompatible
- Service unavailable

## Next Steps After Testing

1. **If all PASS:** Hardware/software integration is working. Document the setup for reproducibility.

2. **If any FAIL:** Debug the failure:
   - Check firmware source for the relevant code
   - Verify protocol contract between firmware and website
   - Check browser console for JavaScript errors
   - Check Supabase logs for failed requests
   - Verify Wi-Fi connectivity
   - Verify Firebase authorized domain configuration

3. **If BLOCKED:** Resolve the blocking dependency and re-run that test.
