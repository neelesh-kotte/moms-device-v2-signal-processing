01 / V1 → V2 → V3

Three iterations. Every failure became a design input.

The project is documented as an engineering research prototype: sensor placement, acoustic coupling, motion, noise, clipping, coverage, and reproducibility are treated as constraints to measure and improve.

V1 · CAPTURE

Hear the signal

Established that the low-cost ESP32 and MAX4466 chain could acquire abdominal-acoustic signals through a stethoscope-style interface.

V2 · VALIDATION

Control the chain

Added controlled capture and validation checks around sample rate, clipping, duplicates, source separation, and the acquisition workflow.

V3 · SENSELOOP

Make limits visible

Connects guided sessions, quality gates, separated profiles, optional check-ins, privacy controls, and uncertainty-aware research summaries.

03 / INDEPENDENT OPERATOR TEST

Could someone else follow the recording workflow?

Two independent people reproduced the physical recording workflow without direct supervision. The point was to test whether the written process was usable beyond its designer.

What this supports

The written workflow was usable by more than the designer in this small sample, including the same stethoscope coupling, MAX4466, ESP32 acquisition path, and quality checks.

What it does not support

It is not a population reliability estimate, universal operator agreement, or clinical reproducibility result.

05 / EXECUTABLE PACKAGE

Run the public calculation from a clean checkout.

The repository contains the runner, dependency list, expected-target file, manifest output, and a deterministic self-test. Raw audio stays outside the repository; the full public download is opt-in.

01 / INSTALL

Prepare the environment

Create a Python environment and install the small, declared dependency set for NumPy, pandas, SciPy, and WAV handling.

02 / VERIFY

Run the self-test

The synthetic self-test exercises windowing, label handling, subject-level aggregation, and the result contract without downloading external audio.

03 / RECOMPUTE

Download and compare

The opt-in run downloads the public corpus, records the archive hash, recomputes the endpoints, and can compare results with the frozen target file.

07 / LIMITS

What this package refuses to claim.

MOM is an engineering prototype. The public evidence package is designed to show the work clearly without stretching it into a medical conclusion.

No diagnosis. MOM does not diagnose disease, screen for illness, or provide medical advice.

No objective hunger meter. The system does not claim to read thoughts or measure a person’s internal state directly.

No clinical validation. Engineering repeatability, external-corpus analysis, and reviewer feedback are not clinical evidence.

No private data exposure. Guest Mode contains demonstration content; private profiles, live device data, and personal recordings remain outside this page.
